# Proc native container ownership contract

Target: Retail **12.1.0, build 69933**, pinned UI source [`09b9db7948abc9b9648dedaab51eb0cf3ee67b31`](https://github.com/Gethe/wow-ui-source/tree/09b9db7948abc9b9648dedaab51eb0cf3ee67b31). This audit establishes source-level ownership and failure boundaries. It does not establish native memory savings or replace client combat, taint, timing, and memory measurements.

## Shared matching is legal; shared public gates are blocked

One Aura may be assigned simultaneously to multiple stable slots. The native slot manager visits every slot for each added or updated Aura, and each slot owns its candidates, preferred assignment, and frame. There is no single-consumer claim on an Aura. This permits duplicate presentation slots, but each slot still creates a native frame and its native duration binding. [Per-slot matching and assignment](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerSlots.lua#L85-L175), [one frame provider per slot](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraContainer.lua#L652-L665).

The intrinsic `AuraButton` already forbids `ChangeParent` before its initialization callback. `SetParent` explicitly checks that restriction. Although the provider runs `initializeFrame` before adding `DenyTaintedAccessWhenAurasAreSecret`, that later restriction is separate from the intrinsic forbidden aspects. Reparenting the button into an independent region wrapper, even inside `initializeFrame`, is not an allowed implementation. [Intrinsic restriction](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraButton.xml#L4-L24), [SetParent check](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleScriptRegionAPIDocumentation.lua#L590-L609), [callback ordering](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerFrameProviders.lua#L75-L93).

An anchor to another region controls layout; it does not change the parent chain that supplies visibility, alpha, and scale inheritance. Slots intentionally use manual anchors, but anchoring a shared-container child to a region wrapper does not grant that wrapper an independent public visual gate. The provider's absence of a later reparent operation does not remove the intrinsic prohibition. CarGOUI therefore retains one bounded reusable container per stable region, with its existing independent public wrapper. The proposed shared-container rewrite is not implemented, and container-count reduction is not claimed. [SetPoint layout arguments](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleScriptRegionResizingAPIDocumentation.lua#L135-L155), [slot layout contract](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerShared.lua#L164-L177).

## Public API and dirty work

There is no public slot-level `SetEnabled`, removal, or `HasAuraSlot` API. `HasAuraSlot` and unregister operations belong to the private managed mixin. The call to `self:HasAuraSlot` inside the secure `AddAuraSlot` implementation does not expose that method to addon Lua. The public partition receives the inbound mixins, not the private mixin. [Private slot methods](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_ManagedAuraContainer.lua#L208-L241), [managed partitions](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_ManagedAuraContainer.lua#L59-L60), [custom partitions](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraContainer.lua#L512-L513), [public XML mixin](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainer.xml#L4-L13).

An empty `includeSpellIDs` map can reject candidates under the permitted helpful-player identity filter. It is not a cheap visual enable switch: `SetAuraSlotCandidateFilters` unconditionally clears candidates and invokes `UpdateAllAuras`, which marks a full container rebuild. Clearing candidates also forces preferred-Aura reassignment. Repeated SHOW events must not use this setter as a replacement for the existing public alpha gate. [Identity inclusion rules](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerUtil.lua#L29-L64), [candidate setter](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraContainer.lua#L434-L440), [candidate reset](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerSlots.lua#L242-L259), [full rebuild](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_ManagedAuraContainer.lua#L20-L56).

Container `SetEnabled(false)` immediately updates dynamic event registrations, then schedules dirty native work. The dirty callback is `RunWhenVisibleOnce`; the container and its ancestor wrappers must remain shown at zero alpha until native clearing can run. Hiding a parent suspends that work. Disabled parsing clears candidates without reading new Auras, and native slot clearing removes the assignment and hides the native child. CarGOUI can request this lifecycle but cannot inspect restricted children to certify its completion. [Enable and event transitions](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainer.lua#L24-L33), [dynamic event predicate](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainer.lua#L157-L188), [dirty scheduling](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_ManagedAuraContainer.lua#L94-L98), [disabled parse](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_ManagedAuraContainer.lua#L502-L509), [slot clearing](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_ManagedAuraContainer.lua#L217-L220).

## Partial construction is not a transaction

`AddAuraSlot` creates/acquires its frame, registers the slot, requests a full refresh, then returns. The provider creates the intrinsic frame, calls `initializeFrame` through `securecallfunction`, applies access restrictions, updates display state, and only then stores the frame in its provider lists. No rollback branch or callback-success result is checked. An error can therefore leave a created frame, an incomplete callback, or a registered slot without a successful outer return. [AddAuraSlot ordering](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraContainer.lua#L400-L420), [provider ordering](https://github.com/Gethe/wow-ui-source/blob/09b9db7948abc9b9648dedaab51eb0cf3ee67b31/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerFrameProviders.lua#L75-L112).

The addon must register its own partial handle before allocation, retain every returned owned object immediately, and commit an `addAttempted` latch before calling `AddAuraSlot`. Readiness requires both a successful outer return and an addon-owned callback-completed flag. If either fails, the slot is uncertain: disable its retained container, preserve the partial handle, and never call `AddAuraSlot` again for that key in the session. There is no public query or removal with which to prove a same-key retry safe. Explicit Retry may retry safe setters on retained objects; an uncertain slot requires Reload. Factories that may allocate before throwing require the same bounded-attempt rule when no returned object is available. No native button, text, duration, or Aura readback is a recovery mechanism.

Completed cleanup does not make uncertain construction safely retryable. Explicit Retry rejects known allocation or slot uncertainty before rebuilding, even when all retained resources were successfully disabled. This is an unavailable recovery operation, not evidence that native cleanup failed.

## Offline fixture requirements

- Apply intrinsic `ChangeParent` rejection before `initializeFrame`, including inside the callback; applying only late access restrictions misses the blocker.
- Keep slot existence in the fixture's private registry. Reject duplicate keys without exposing a public `HasAuraSlot` or removal API.
- Model every stable slot independently so the same Aura can supply several slots. Do not infer shared native duration bindings.
- Exercise both callback failure with a successful outer return and failure after native slot registration. Neither may permit a second same-key `AddAuraSlot` attempt.
- Separate immediate event-unregistration requests from queued assignment/binding clearing. Dirty work requires visible ancestors; zero alpha does not prevent it.
- Count actual returned allocations independently from addon registry sizes. Mocks establish bounded addon behavior, not target-client memory or CPU results.
